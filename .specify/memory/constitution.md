# QA Pilot Constitution

## Core Principles

### I. Semantic Context Only (No Raw HTML to LLM)
All interactions between the test execution engine and the AI/LLM MUST use semantic Accessibility (a11y) Tree snapshots, filtered console error deltas, and failed network request summaries. Passing raw HTML/DOM dumps to the LLM is strictly prohibited to preserve token efficiency, deterministic element targeting, and low triage latency.

### II. Test-as-Code & Zero-Database Persistence
Every test case, environment configuration, and fixture MUST be stored as human-readable, schema-validated YAML or JSON files directly in the repository (`tests/projects/<project>/`). The system MUST NOT depend on an external relational or document database for test definitions or run artifacts (`tests/runs/<run_id>/`).

### III. Production Safety & Secret Redaction (NON-NEGOTIABLE)
Execution against environments marked `is_production: true` MUST hard-block any test specification containing `destructive`, `financial`, or `data-creation` tags, as well as any target URL outside the environment's explicit domain whitelist. Furthermore, all secrets loaded from `.env.local` MUST be redacted to `[REDACTED]` before being emitted to SSE streams, written to run artifacts, or included in AI prompts.

### IV. Hybrid CDP Execution & Actionable Visual Evidence
Test runs MUST use a hybrid execution architecture built on **Chrome DevTools Protocol (CDP)**: direct CDP browser automation and telemetry collection (attaching to or launching Chrome on `--remote-debugging-port=9222` for step execution, `Accessibility.getFullAXTree`, `DOM.getBoxModel`, `Runtime` console logs, and `Network` failure capture), combined with isolated, clean-slate Local AI CLI subprocesses (`claude` / `agy` / `gemini` in `-p` non-interactive print mode with `chrome-devtools-mcp`) for failure Root Cause Analysis (RCA) and multimodal test generation, streaming real-time progress over Server-Sent Events (SSE). Every failed step MUST capture both a raw screenshot and a `sharp`-annotated screenshot (dotted red bounding box + error badge), paired with console/network failure logs and an AI RCA in Vietnamese.

### V. Safe Multi-Contributor Git Synchronization
Git operations exposed to QA users MUST enforce a safe synchronization flow (`pull --rebase` prior to `commit` and `push` via `simple-git`). When merge conflicts occur on YAML specs, the system MUST surface a structured step-by-step diff for visual resolution rather than exposing raw Git conflict markers.

### VI. Minimalist Interface & Plain Functional Language
All user-facing text, labels, buttons, statuses, and messages MUST use plain, concise, neutral, functional language. Using emojis or decorative symbols in UI labels, buttons, badges, or notifications is strictly prohibited. Marketing or hyperbolic phrasing (such as "1-click", "magic", "smart", "super-fast", "auto-heal") MUST NOT appear anywhere in the interface or copy. Form controls MUST hide irrelevant fields based on context (e.g., hiding input value fields for `open` and `click` actions) to keep the workspace clean and distraction-free.

## Architecture & Technology Constraints

- **Monorepo Topology**: Node.js + Express + TypeScript backend (`server/`, port `4000`) and React 18 + Vite + Ant Design (`antd` v5) + minimal CSS variables SPA (`client/`, port `3000`). No Tailwind CSS or PostCSS utility bloat.
- **Browser & Inspection Protocol**: Browser automation and telemetry collection MUST operate via **Chrome DevTools Protocol (CDP)** (`http://127.0.0.1:9222` and `chrome-devtools-mcp`), enabling direct attachment to local Chrome sessions, low-overhead DOM/a11y inspection, and real-time network/console stream capture.
- **Artifact Hygiene**: `tests/runs/`, `tests/temp/`, `*.png`, `*.har`, and `**/.env.local` MUST be excluded from version control via `.gitignore` at all times.

## Quality Gates & Execution Workflow

- **Schema Validation**: Every YAML test spec generated by AI or edited in the UI MUST pass structural validation (`id`, `title`, `environments`, `steps`, `assertions`) before saving to disk.
- **Pre-Flight Safety Check**: The runner service MUST evaluate environment rules and tag blocks prior to spawning any CLI subprocess.
- **Non-Blocking Optional Steps**: Steps marked `optional: true` MUST respect their configured `timeout_ms` and log warnings on failure without aborting the test run.
- **Copywriting & UI Hygiene Gate**: Every UI view MUST be verified to contain zero emojis, zero exaggerated marketing phrases, and minimal visual clutter.

## Governance

This Constitution supersedes ad-hoc implementation choices across `server/`, `client/`, and `tests/`. Any amendment to Core Principles requires explicit user approval, documentation of rationale, and a corresponding semantic version bump:
- **MAJOR**: Removal or weakening of a Core Principle or production safety guardrail.
- **MINOR**: Addition of a new principle, architectural constraint, or mandatory quality gate.
- **PATCH**: Wording clarifications or non-semantic refinements.
